# 1. Storage APIs

# BNX Mail - Storage & Vault API Documentation

The **Storage** system in **BNX Mail** manages two primary aspects:
1. **Mailbox Storage Quota API (`/api/mail/storage-quota`)**: Real-time mailbox disk space tracking, usage calculation, limit enforcement via Dovecot/IMAP, and User settings.
2. **File Storage Vault API (`/api/vault`)**: Cloud drive / personal file storage allowing users to upload, manage, and download persistent files.
3. **Draft & Attachment Storage Engine**: Local disk storage service with automatic quota enforcement.

---

## 2. Mailbox Storage Quota API (`/api/mail`)

### 2.1 Get Mailbox Storage Quota

Retrieves real-time storage usage, overall quota limit, and consumption percentage for the authenticated user's mailbox. Uses low-level `doveadm quota get` or IMAP `QUOTA` RFC extension.

- **Endpoint:** `GET /api/mail/storage-quota`
- **Method:** `GET`
- **Authentication:** Required (Bearer Token)
- **Controller:** [MailReceiveController.java](file:///c:/Users/ASHWIN/Downloads/BNX-MAIL-BE/src/main/java/com/btctech/mailapp/controller/MailReceiveController.java#L169-L193)
- **Service:** [MailReceiveService.java](file:///c:/Users/ASHWIN/Downloads/BNX-MAIL-BE/src/main/java/com/btctech/mailapp/service/MailReceiveService.java#L190-L261)

#### Headers
```http
Authorization: Bearer <accessToken>
```

#### Response (`200 OK`)
Wrapped in standard `ApiResponse<StorageQuotaDTO>`:
```json
{
  "success": true,
  "message": "Storage quota fetched successfully",
  "data": {
    "email": "john.smith@bnxmail.com",
    "storageLimit": 5368709120,
    "storageUsed": 722518016,
    "storagePercentage": 13.458
  },
  "timestamp": 1712836200000
}
```

#### Fields Description (`StorageQuotaDTO`)
| Field | Type | Description |
|---|---|---|
| `email` | `string` | The user's mailbox email address |
| `storageLimit` | `number` (long) | Total allocated storage capacity in **bytes** (Default: 5 GB = `5368709120` bytes, or plan limit) |
| `storageUsed` | `number` (long) | Currently used storage space in **bytes** |
| `storagePercentage` | `number` (double) | Calculated usage percentage (`(storageUsed / storageLimit) * 100`) |

## 3. File Storage Vault API (`/api/vault`)

The **Vault** acts as a personal cloud drive for storing files (documents, images, archives) directly associated with the user account.

### 3.1 Upload File to Vault

Uploads a file into personal storage. Maximum file size allowed is **5MB**.

- **Endpoint:** `POST /api/vault/upload`
- **Method:** `POST`
- **Authentication:** Required (Bearer Token)
- **Content-Type:** `multipart/form-data`
- **Controller:** [VaultController.java](file:///c:/Users/ASHWIN/Downloads/BNX-MAIL-BE/src/main/java/com/btctech/mailapp/controller/VaultController.java#L40-L58)

#### Form-Data Parameters
| Parameter | Type | Required | Description |
|---|---|---|---|
| `file` | `File` (binary) | **Yes** | The file to upload (Max size: 5 MB) |

#### cURL Example
```bash
curl -X POST "http://localhost:8080/api/vault/upload" \
  -H "Authorization: Bearer <accessToken>" \
  -F "file=@/path/to/invoice.pdf"
```

#### Response (`200 OK`)
```json
{
  "message": "File uploaded successfully",
  "id": 14,
  "filename": "invoice.pdf"
}
```

#### Error Responses
- `400 Bad Request` (File size exceeds limit):
  ```json
  {
    "error": "File size exceeds the 5MB limit"
  }
  ```
- `500 Internal Server Error`:
  ```json
  {
    "error": "Could not upload the file: <details>"
  }
  ```

### 3.3 Download File

Downloads the raw binary content of a file by its ID. Enforces ownership verification so users can only access their own files.

- **Endpoint:** `GET /api/vault/{id}/download`
- **Method:** `GET`
- **Authentication:** Required (Bearer Token)
- **Path Parameter:**
  - `id` (`number`): The ID of the file in the vault.
- **Controller:** [VaultController.java](file:///c:/Users/ASHWIN/Downloads/BNX-MAIL-BE/src/main/java/com/btctech/mailapp/controller/VaultController.java#L72-L87)

#### Response (`200 OK`)
- **Content-Type:** Matches uploaded MIME type (e.g., `application/pdf`, `image/png`, `application/octet-stream`)
- **Headers:** `Content-Disposition: attachment; filename="<original_filename>"`
- **Body:** Raw binary byte stream

#### Error Response (`404 Not Found`)
```json
{
  "error": "File not found"
}
```
*(or `"Unauthorized access to file"` if requested file belongs to another user)*

## 7. HTTP Status & Error Codes

| Status Code | Description | Typical Cause |
|---|---|---|
| `200 OK` | Success | Operation succeeded. |
| `400 Bad Request` | Bad Request / File Size Exceeded | File size exceeds 5MB or invalid parameters. |
| `401 Unauthorized` | Auth Failure / Session Expired | Missing or expired JWT Bearer token. |
| `404 Not Found` | Not Found / Access Denied | File ID does not exist or unauthorized access. |
| `500 Internal Server Error` | Server Exception | Storage read/write error or server failure. |

**Standard Response Wrapper:**
Unless noted otherwise, all JSON responses use the following wrapper format:
```json
{
  "success": true, // or false on error
  "message": "Operation successful",
  "data": { ... }, // the actual payload
  "timestamp": 1712836200000
}
```

## 3. Two-Factor Authentication (2FA)

### 3.1 Initiate 2FA Setup
Generates the secret and QR code URI for authenticator apps.
- **Endpoint:** `POST /api/users/2fa/setup`
- **Auth Required:** Yes
- **Body:** `{}` (Empty JSON object)
- **Response `data`:** 
```json
{
  "secret": "JBSWY3DPEHPK3PXP",
  "qrCodeUri": "otpauth://totp/BNXMail:siva?secret=JBSWY3DPEHPK3PXP&issuer=BNXMail"
}
```

### 3.2 Verify and Enable 2FA
Verify the code from the authenticator app to fully enable 2FA.
- **Endpoint:** `POST /api/users/2fa/verify`
- **Auth Required:** Yes
- **Body:** 
```json
{
  "code": "123456" // The 6-digit TOTP code
}
```
- **Response `data`:** `null` (Success message in wrapper)

### 3.3 Disable 2FA
Turn off two-factor authentication.
- **Endpoint:** `POST /api/users/2fa/disable`
- **Auth Required:** Yes
- **Body:** `{}` (Empty JSON object)
- **Response `data`:** `null`

*(Note: There is also an older `/api/users/2fa/enable` route that might be called before `/verify` depending on the exact flow used, but typically `setup` -> `verify` is the standard).*

### 4.2 Create Sub-ID
Create a new sub-account under the current user's domain/prefix.
- **Endpoint:** `POST /api/subid/create`
- **Auth Required:** Yes
- **Body:** 
```json
{
  "prefix": "child",            // Will create child.siva@bnxmail.com
  "password": "SecurePassword123" 
}
```
- **Response `data`:** Details of the newly created sub-user account.

## 6. Payment & Subscription (External API)

The `bnx-account-ui` fetches active subscription details to display in the Billing tab. Note that this endpoint points to a different service domain.

### 6.1 Get Active Subscription
Fetches the active Cliks Business subscription details for the user.
- **Endpoint:** `GET https://cliks.beta-softnet.com/api/v1/business/subscription/{userEmail}`
- **Auth Required:** No (in the frontend implementation, it makes a direct GET request)
- **Body:** None
- **Response:**
```json
{
  "success": true,
  "message": "Subscription retrieved",
  "data": {
    "plan_name": "Pro Business Plan",
    "subscription_days_remaining": 34,
    "when_subscribed": "2026-09-01T10:00:00Z",
    "next_due_date": "2026-11-04T10:00:00Z",
    "email": "user@example.com"
  }
}
```
*(Note: If the user is on the "Free Plan" or `subscription_days_remaining` is 0, the UI will display a prompt to upgrade instead).*
